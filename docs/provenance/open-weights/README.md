Part C has made no Baseten inference calls. The scorer requests exactly meta-models/muse-spark-open-1026 at https://inference.baseten.co/v1, effort low. A small authored-text probe comes first; HTTP 404 skips every Baseten comparison without another slug. The checked official pages name the model family but did not verify this exact dated slug.

Only authored text fixtures and simulated ranking inputs for tuning seeds 1, 2, 4, 5, 8 and 9 are allowed. Audio and recording-derived transcripts never go to Baseten. Seeds outside the tuning set are refused before a request. No deployed function imports the comparison client, and production callRanker still refuses non-Meta providers.

Eight authored card comparisons cover D4-1, D4-2, NEAR-MISS, names, a two-card report, advice, a non-report and a vague count. They use Candidate A's prompt and the unchanged reply schema. The runner sends json_schema with strict true and validates the returned JSON locally before production cleaning. Baseten's [structured output documentation](https://docs.baseten.co/inference/structured-outputs), checked 30 Oct 2026, says Muse Spark Open accepts the format but does not enforce the schema. Unsupported shape is a recorded failure; there is no JSON repair retry.

Six first-Alert ranking comparisons rebuild the input and verify both its hash and the saved full input against Task 15a's results. The production request builder produces the prompt, schema, temperature and cap; only script provider/model/effort and the provider's token-cap parameter change. Production validateRanking is reused unchanged. No statistics or frozen ranking settings are edited.

On a paid run, fixture-results.jsonl holds authored inputs/outputs; ranking-results.jsonl holds simulated inputs/outputs and the saved Meta comparison; run-log.jsonl holds content-free model, base URL, effort, timing, token, attempt and outcome metadata. These files are created only by actual calls. Recording artifacts and the spending ledger stay in ignored test-audio/results. The aggregate comparison appears in the offline scoring report, with missing/skipped results explicit.

The exact dated slug's rate was not separately stated; this family rate is the forecast and ledger assumption.
